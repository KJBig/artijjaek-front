# UI와 스타일 가이드

## 스타일 적용 범위

`src/style.css`는 box sizing, body, 링크, 버튼, `#app`, 이미지 등 최소 reset을 담당한다. 화면 고유 스타일은 SFC의 `<style scoped>`에 둔다. 공통 요소를 전역 selector로 추가하기 전에 기존 컴포넌트로 캡슐화할 수 있는지 확인한다.

## 현재 시각 언어

- 기본 배경: 흰색 또는 `#fafaff`로 이어지는 밝은 gradient.
- 브랜드 강조: `#6675e0`에서 `#7652c9`로 이어지는 보라색 gradient.
- 카드: 약한 보라/회색 border, 12~16px radius, 낮은 농도의 shadow.
- 텍스트: 제목은 짙은 남보라/회색, 보조 문구는 `#6e6a7e` 계열.
- 주요 버튼: 브랜드 gradient와 흰색 텍스트.
- 보조 버튼: 흰 배경, 보라색 테두리와 텍스트.

새 UI는 대상 페이지의 실제 수치와 컴포넌트를 먼저 재사용한다. 현재 디자인 토큰 시스템은 없으므로 임의의 새 색과 radius를 늘리지 않는다.

## 반응형

현재 CSS는 페이지별 media query를 사용한다. `HeaderNav.vue`는 768px 이하에서 접히는 메뉴, 480px 이하에서 작은 로고와 버튼을 제공하고, 폼 화면은 주로 640px 이하에서 padding을 줄인다.

- 고정 폭 대신 `width: min(..., 100%)` 패턴을 사용한다.
- 모바일에서 가로 overflow가 생기지 않는지 확인한다.
- 긴 회사명·카테고리명은 말줄임 또는 스크롤 같은 명시적 처리를 둔다.
- 데스크톱과 모바일 모두에서 팝업, 드롭다운 z-index와 sticky header의 관계를 확인한다.

## 접근성

기존 코드의 `aria-label`, `aria-expanded`, `aria-live`, `role="alert"`, label/input 연결을 유지·확장한다.

- 아이콘 버튼에는 접근 가능한 이름을 제공한다.
- 폼 label의 `for`와 input `id`를 연결한다.
- 키보드 focus는 `:focus-visible`로 시각화한다.
- 비동기 결과와 오류는 텍스트로 전달하고 색상만으로 상태를 표현하지 않는다.
- 모달은 `Teleport to="body"` 패턴을 사용하되 새 모달에는 초기 포커스, Escape 닫기, 포커스 복귀도 검토한다.
- 이미지 alt는 목적에 맞게 작성한다. 장식 이미지는 빈 alt를 고려한다.

## 화면 상태

모든 서버 연동 화면은 해당되는 상태를 설계한다.

- 초기 로딩 및 재시도
- 실제 빈 결과
- 인증 또는 요청 오류
- 제출 중 중복 클릭 방지
- 성공 피드백

인증 치명 오류에는 `AuthErrorPanel.vue`, 성공 확인에는 기존 `SuccessPopup.vue` 또는 인접 페이지의 팝업 패턴을 우선 검토한다.
